01 — Architecture sécurisée (Salve Italia)
COUCHE 01
🌐 Frontend React + Vite
  • Zero trust : score, correct_answer et prompt consul jamais calculés côté client
  • Uniquement VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY exposées
  • Zéro clé service, zéro clé Anthropic dans le bundle
  • CSP stricte, pas de script tiers superflu sur les pages sensibles
  • Sanitization des réponses libres et transcriptions avant envoi
COUCHE 02
🔀 API Backend Node.js/Express
  • JWT Supabase validé sur chaque route, rôle jamais lu depuis le client
  • Rate limiting différencié par route (voir §04)
  • CORS restreint au(x) domaine(s) Vercel du site
  • Endpoints IA (/embassy-agent, génération de questions) isolés et quotés
COUCHE 03
⚙️ Services métier
  • Un service = une responsabilité (Auth, TestEngine, EmbassySession, Document, AI)
  • ANTHROPIC_API_KEY confinée à AIService, nulle part ailleurs
  • Aucune requête SQL par concaténation — client Supabase paramétré uniquement
  • Logs structurés sans PII (voir §03)
COUCHE 04
🗄️ Supabase / Postgres
  • RLS activé sur toutes les tables sans exception
  • Un étudiant : ses propres lignes uniquement ; un enseignant : ses classes
  • Backups automatiques vérifiés (fréquence, rétention)
  • audit_logs pour toute action admin sensible
COUCHE 05
🔐 Auth & Sessions
  • Hachage des mots de passe géré nativement par Supabase Auth
  • Comptes créés uniquement par l'admin, pas de self-registration
  • MFA obligatoire pour les comptes admin
  • Déconnexion automatique après inactivité (utile sur poste partagé)
COUCHE 06
☁️ Déploiement Vercel / Railway
  • Variables d'env dans les dashboards Vercel/Railway, jamais commitées
  • HTTPS + HSTS natifs, activés
  • Staging obligatoire avant mise en production
  • Clés dev/staging/prod séparées (projets Supabase distincts si possible)

Réseau, API & Headers HTTP
NETWORK
✓
Content Security Policy (CSP) configurée
Bloque XSS, clickjacking, injections inline. Tester sur csp-evaluator.withgoogle.com
CRITIQUE
✓
Headers de sécurité HTTP complets
X-Frame-Options: DENY · X-Content-Type-Options: nosniff · HSTS · Referrer-Policy
IMPORTANT
✓
Protection CSRF sur toutes les mutations
Création de compte, dépôt de document, envoi de message à l'agent : jamais de mutation via une simple requête GET.
CRITIQUE
✓
Rate limiting différencié par endpoint
/login : 5/min · /embassy-agent : quota par étudiant (EF-59) · /questions (écriture) : enseignant/admin uniquement · /documents/upload : limité.
CRITIQUE
✓
TLS 1.2+ minimum, certificat valide & renouvelé
Natif sur Vercel, Railway/Render et Supabase — vérifier qu'aucun sous-domaine ne retombe en HTTP.
CRITIQUE
✓
Pas de données sensibles dans les URLs
Token de session, ID de document → jamais en query string. Passer par le body (POST) ou l'en-tête Authorization.
IMPORTANT
✓
WAF non indispensable au lancement, mais disponible si besoin
Cloudflare gratuit en façade de Vercel reste une option low-cost à activer si le trafic ou les tentatives d'abus l'exigent.

Journalisée pour l'enseignant sans bloquer automatiquement la session, pour rester tolérant à une connexion instable (ENF-03).
